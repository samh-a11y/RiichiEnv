## 调研结论（写进了 PROJECT/RESOURCES）
- RiichiEnv 是 Rust+Python(maturin) 高性能麻将环境，**原生支持三麻 + MJAI + Mortal Bot 兼容**（README 称 100 万+半庄无错跑通 MortalAgent）。`game_mode="3p-red-half"` = 天凤三麻半庄。
- 关键接口：`obs.new_events()`（出 MJAI 事件）+ `obs.select_action_from_mjai(resp)`（MJAI 动作→合法 Action）。原生 `riichienv_ml.agents.Agent` 走自带编码器，**不适用我们三个 Mortal 模型**（各用各的 libriichi obs）。
- 三模型引擎/维度核实：
  - v8（gpuo `/root/sanma`）：`libriichi-sanma` .so（575×34/AS44），权重 `runs/v8_bc/model.pth`(101MB)，net SanmaNet 384×24。**无 stdin/stdout bot**（in-process agent）→ 需自写 MJAI wrapper（最重）。
  - joint-v2：`../Mortal3/train/sl3p-joint-v2/archive/mortal.final.pth`(127MB)，我们 `libriichi3p --features joint`（obs(752,27)/AS81），有 `mortal/bot.py`（stdin/stdout MJAI）。
  - community：`../Mortal3/community_3p/v0.1.0/`（`libriichi` 模块 + `mortal.pth` 273MB + bot.py，775×34/AS44），用户告知较弱。
- **核心设计**：桥接在 MJAI 层（不统一 obs/action）；每个模型 = MJAI 子进程引擎（回避 python/torch/.so 版本冲突）；裁判口径对齐 Mortal3/gpuo（avg placement 公平 2.00、CRN、半庄、pts[3,0,-3]）；不改上游 Rust，接入代码建在 `arena3p/`。
- **头号风险**：三麻 MJAI 方言对齐（拔北/座位 %4/无 2–8 万）→ change-001 步骤 1 先做逐事件 diff（参照 `Mortal3/.claude/MJAI_SCHEMA_3P.md`）。
