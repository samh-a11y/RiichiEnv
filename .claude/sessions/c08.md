# c08 — 真机 ankan 被误判非法回退的根因定位与修复（change-003）

> 日期：2026-07-14　｜　承 c07（本机 4070 ranked 上线）

## 触发
用户贴出本机 Nosam（ranked）日志：反复出现
```
[Nosam] WARN 动作不在合法集，回退：act={'type':'ankan','actor':0,'consumed':['E','E','E','E']}
        legal_types=[...,'ankan']
```
`legal_types` **明明含 `ankan`**，却每次都被 `_sanitize` 判非法回退成打牌（`consumed` 后来也见 `['2s']×4`）。= 该暗杠的手不杠，少一番 / 宝牌指示牌不翻新，实打实对局损失。

## 根因（读 riichienv-core Rust 源，结论链闭合）
1. **服务器合法集里的 ankan 带 `pai`**：`state_3p/legal_actions.rs:152` 构造 ankan 合法动作用
   `Action::new(ActionType::Ankan, Some(lowest), consume, Some(pid))`（`tile=Some`）；而
   `action.rs::to_mjai`（132-138 行）**只要 `tile` 是 `Some` 且非 Tsumo/Ron/Riichi 就插 `pai`**——
   ankan 也不例外 ⇒ `{"type":"ankan","actor":0,"pai":"E","consumed":["E","E","E","E"]}`。
2. **bot / 标准 mjai 的 ankan 不带 `pai`**（`replay/mjai_replay.rs:117` 即 `Ankan{actor,consumed}`）。
3. **客户端 `_match` 对 ankan 比 `pai`** → `"E" == None` 恒 False → 每次暗杠误判非法回退。
4. **但服务器收 bot 回传的无 pai ankan 时是接受的**：`observation/mjai_select.rs::select_action`
   对 ankan 只按 `consumed_matches` 匹配，**pai 二次校验（168 行）只对 `Chi|Pon|Daiminkan|Kakan`**，
   不含 ankan/kita ⇒ **无需给出站 ankan 补 pai**，纯客户端兜底 bug。
   （kita 两侧都带 `pai="N"`——`state_3p/sanma.rs:164` 也 `Some(tile)`——所以 kita 不受影响。）

## 修复
`online3p/client.py::_match`：镜像服务器 `select_action` 的接受逻辑——
- 副露类先按 `sorted(consumed)` 匹配；
- `pai` 二次校验**只对 chi/pon/daiminkan/kakan 且两侧都给 pai 时**做；ankan/kita 不比 pai。
dahai / reach / hora / none 逻辑不变。

## 验证
新增仓库回归测试 `online3p/test_action_match.py`（纯逻辑，stdlib，`python -m online3p.test_action_match`）：
9/9 PASS——真机原样 ankan E/2s 现匹配、`_sanitize` 端到端保留 ankan 不回退、不误伤（ankan 3s≠E）、
kita/pon（保持 aka 严格）/dahai 无回归。
